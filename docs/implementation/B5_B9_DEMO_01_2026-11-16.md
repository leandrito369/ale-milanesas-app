## Contrato de integración para Antigravity

Compatibilidad cotejada con PR Antigravity #93, SHA `773feb08529f7feb65c112e91c3954247e33b29a`: nombres filtro/form, direcciones planas y propiedades de presentación alineadas sin modificar vistas. Variables transversales esAdmin/esVendedor/esRepartidor se derivan de Authentication mediante ControllerAdvice, nunca del formulario. CSRF queda a cargo de Spring Security; el parser de negocio ignora _csrf (puede existir hidden explícito y automático), sin debilitar su validación.

Todas las vistas son nombres Thymeleaf bajo `templates/demo/`. No existen en esta rama: su implementación pertenece a Antigravity. Login/cambio/inicio históricos quedan intactos. No usar JS, CDN, estilos inline ni th:utext. Usar th:text y th:action para CSRF, evitando duplicar el hidden automático si lo genera Thymeleaf. Formularios mutantes requieren token CSRF del servidor.

Todos los controladores demo ausentes en prod. GET/POST de formularios UC03/43 tienen el mismo gate y rol en cadena web. Un actor sin sesión obtiene 401; autenticado no autorizado 403. El gate de seguridad puede responder antes del controlador ausente.

Filtros UC33: idCliente, nombre, telefonoPrincipal, zona, estado ACTIVO/INACTIVO.
UC35: idProducto, nombre, tipoProducto ELABORADO/REVENTA, activo true/false.
UC34: idPedido, idCliente, fechaReparto ISO, estado PENDIENTE/ENTREGADO/CANCELADO, canalOrigen INTERNO/ONLINE. Vacíos opcionales se convierten a null; claves desconocidas o repetidas y valores NUL rechazados. No aceptar actor, rol, token ni idSesion como entrada.

UC03 nombres exactos: idCliente, fechaReparto, claveIdempotencia; items[0..2].idProducto y items[0..2].cantidadSolicitada; calle, numero, piso, unidadFuncional, localidad, provincia, referencia, zona (campos planos HTML; ensamblados como DireccionEntrega B3). Primera fila obligatoria; segunda/tercera solo se omiten si ambos campos están vacíos. Calle/localidad obligatorias. B3 conserva validación de cantidades positivas, escala <=3, productos sin duplicar, fecha, clientes/precios/política, congelamiento e idempotencia. Nunca mandar precio/total como autoridad. El modelo form presenta una lista items de tres Map con propiedades idProducto/cantidadSolicitada, preservando texto inválido para corregir. Es compatible con form.items[0].idProducto de PR93. GET admite idCliente opcional desde UC33.

La clave UUID se genera en GET y se conserva en error/reintento. No debe reutilizarse para un pedido intencionalmente distinto; B3 compara cliente/canal al reconocer una clave existente, no un hash íntegro del payload. No afirmar una garantía distinta.

UC43: idPedido proviene exclusivamente de URL; idUsuarioRepartidor requerido, motivoReasignacion opcional. Vacío → null para primera asignación; B3 exige motivo al reemplazar. Sin selector UC56 ni consulta de asignación vigente. No prometer reasignación completa P0. ID de fixture REPARTIDOR: 91003.

Proyección UC33: idCliente, nombre, telefonoPrincipal, direccion, zona, estado, categoriaComercial. UC35: idProducto, nombre, descripcion, tipoProducto, codigoUnidadVenta, activo (seis campos). UC34 ADMIN: idPedido, idCliente, fechaReparto, estado, canalOrigen, fechaHoraCarga. VENDEDOR agrega categoriaComercialAplicada/totalOriginal. La vista debe discriminar variante del DTO antes de acceder a campos comerciales; no evaluar totalOriginal en PedidoAdministrativo. No enriquecer con entidades, costos, dirección o detalles no devueltos.

## Bootstrap privado reproducible

Requisitos: JDK21 completo, Maven3.9+, Docker Compose y PostgreSQL 17.11. Solo PC/VM privada; no registrar puertos en previews públicas. El script fija backend 127.0.0.1:8443 y DB 127.0.0.1:55439. No usar prod, DB del negocio ni el runbook histórico de aceptación V1/V2.

1. Checkout del SHA revisado; guardar `git rev-parse HEAD` y árbol limpio. Ejecutar `mvn -B -ntp clean verify` con Docker disponible.
2. Generar secreto aleatorio ALE_DB_PASSWORD y ALE_DEMO_CREDENTIAL en sesión privada mediante gestor de secretos; no imprimirlos ni usar credenciales predeterminadas. `bash scripts/demo/entorno.sh db` crea ale_milanesas_demo en contenedor separado con almacenamiento tmpfs. No comparte compose/volumen dev.
3. `scripts/demo/tls.sh` genera certificado/PKCS12 con mkcert y openssl en ALE_DEMO_TLS_DIR nuevo, absoluto y externo al checkout (CA previamente confiada por operador con mkcert -install); no instala trust stores automáticamente. Generar certificado localhost con SAN localhost/127.0.0.1 mediante CA local confiable (por ejemplo mkcert en PC del operador), instalar su CA en navegador y construir PKCS12 fuera de Git. Certificado y clave/contraseña no deben enviarse al chat, logs ni PR. Configurar ALE_DEMO_KEYSTORE (ruta absoluta), ALE_DEMO_KEYSTORE_PASSWORD. No usar curl -k, no desactivar Secure/CSRF/Origin ni SSL.
4. `bash scripts/demo/entorno.sh run`: arranca JAR con perfil demo, HTTPS directo, ambos flags autorizados true y Flyway V1–V3. Verificar health mediante HTTPS confiable. Detener proceso antes del seed inicial.
5. `bash scripts/demo/entorno.sh seed`: usa JDBC fijo a DB demo; exige tablas de maestros vacías; credenciales protegidas con BCrypt y sin sesiones prefabricadas. El Java de scripts solo ejecuta DML de fixtures sintéticas sobre esquema ya migrado. Para Maven personalizado se admite MAVEN_CMD (ruta a ejecutable, sin argumentos).
6. Volver a run. Usuarios demo_administrador / demo_vendedor / demo_repartidor con credencial efímera elegida por operador. Cliente 92001, producto 93001, repartidor 91003. Política y precio son datos sintéticos de ensayo, no defaults comerciales. Login real en /web/login. Antes de F, navegar por URL directa: inicio no contiene enlaces nuevos.
7. Solo después de integrar vistas y aprobación humana: circuito UC33→UC35→UC03→UC43→UC34 con VENDEDOR y ADMIN. Mis entregas es ilustrativa. Registrar status, SHA y evidencia DB con columnas seleccionadas, nunca hashes/tokens. Probar rechazo REPARTIDOR a UC34 web y CSRF/origen. Verificar snapshots del pedido/detalle y asignación vigente.
8. Parar JVM antes de `bash scripts/demo/entorno.sh reset` o `teardown`; reset destruye únicamente proyecto Docker ale-b5-demo y sus datos efímeros, exige migración y seed de nuevo. No hay migraciones inversas. Retirar secretos, certificados y sesiones del entorno de prueba al terminar.

Origin: permitido coincide exactamente con https://localhost:8443; externo y literal null se rechazan; cabecera ausente sigue permitida con CSRF (comportamiento existente probado). CSS requiere recurso real de Antigravity; el permiso no crea la hoja.
