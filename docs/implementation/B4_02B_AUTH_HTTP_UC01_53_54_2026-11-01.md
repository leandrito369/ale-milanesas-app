## Seguridad y límites de exposición

- **Únicamente API interna `/api/v1/**` con Bearer**. `login` es la única ruta API sin credencial; no hay cookie aceptada por el filtro. CSRF desactivado **solo** en esta cadena que no autentica cookies. La cadena web existente mantiene CSRF/deny-all; **NO se habilita aún un adaptador de cookie Thymeleaf**.
- No se abre ningún endpoint POST/PUT/PATCH/DELETE **de negocio**. El endpoint UC54 es mutación de credencial (excepción de seguridad ratificada).
- Errores sanitizados; `Cache-Control: no-store`, `Pragma: no-cache`, sin enviar UUID/rol/token en campos extra de la respuesta ni logs intencionales. HTTPS debe exigirse en proxy/servidor al desplegar.
- `LimiteIntentosLogin` es solo defensa por proceso JVM. No pretende asegurar despliegue con más de una instancia ni resistir cambios de IP por NAT/proxy. **Antes de exponer públicamente, B4-02C exige limitador distribuido en ingress o arquitectura aprobada y prueba de tasas/rate limiting**, junto con hardening de TLS y logs.
- El código no incluye configuración de secretos de terceros, notificaciones de restablecimiento ni una API Cliente ONLINE, ni modifica F04.
